# Troubleshooting

| Symptom | What to check |
| --- | --- |
| `error: externally-managed-environment` / `× This environment is externally managed` | You are installing into system Python (Debian 12+, Ubuntu 23.04+, Fedora). Create and activate a dedicated virtual environment (`python3.11 -m venv .venv && source .venv/bin/activate`), then install `requirements/runtime.lock`. Never pass `--break-system-packages` and never use `sudo pip`. |
| `The virtual environment was not created successfully because ensurepip is not available` | The distribution's `venv` package is missing. Install it (`sudo apt install python3.11-venv` on Debian/Ubuntu) and recreate the environment. |
| `poptrap` is not found | A source-tree install creates no launcher: run `python -m poptrap` from the checkout, or install the built wheel to get `poptrap`. Otherwise activate the environment used for install, or run that environment's Python with `-m poptrap`. Verify `--version` before diagnosing older installs. |
| `POPTRAP error: Missing or incompatible runtime dependencies: …` (exit 2) | The environment is inactive or the locked install was skipped or interrupted. Activate it, re-run `python -m pip install --require-hashes --only-binary=:all: -r requirements/runtime.lock`, then confirm with `poptrap --check`. `--version` still works without dependencies, so it cannot detect this. |
| Pip cannot find a compatible locked wheel: `ERROR: Could not find a version that satisfies the requirement pydantic-core==2.50.4` | Use CPython 3.11 on a target with compatible wheels. Check `python -V` and `python -c "import platform; print(platform.machine())"`, and normal package index access. Do not bypass hashes or lower dependency floors. On Android Termux this failure is expected and permanent: Termux reports the bare `linux_aarch64` platform tag (Bionic, not glibc), and `pydantic-core` publishes no wheel for it. Termux is not a supported install target for the candidate — see [installation](installation.md#android-termux-not-supported). |
| `ERROR: In hash-checking mode, no hash for …` or `THESE PACKAGES DO NOT MATCH THE HASHES` | The lock was edited or a cached download is corrupt. Restore it (`git checkout -- requirements/runtime.lock`), run `python -m pip cache purge`, and reinstall. Never delete or replace a hash to get past this. |
| No interactive TUI: `Standard input/output is not attached to an interactive terminal` or `TERM is set to 'dumb'` (exit 2) | Open a real UTF-8 terminal, at least 44 × 12 (80 × 24 recommended), with `TERM` such as `xterm-256color`. Editor outputs, CI and redirected streams may support `--check` but not the TUI. |
| `Notice: Terminal size is 40x10 (minimum 44x12)` or `Notice: Limited 16-color terminal detected` | Cosmetic readiness notices from `--check`, not failures. Enlarge the window or reduce font zoom, and set `TERM=xterm-256color` (unset `NO_COLOR`) for the intended palette. |
| Install claims cannot be reproduced | Run `python3 tools/verify_install.py` from the repository root. It re-verifies lock hashes against PyPI, wheel availability per platform tag, and a complete fresh install into clean virtual environments. |
| Configuration warning | `poptrap --check` shows startup fallback notices. Validate the actual file with `poptrap --validate-config --config PATH`; repair its TOML or choose a new file. The application does not replace invalid settings unless you save explicitly. |
| Save failed or preset skipped | Check free space, directory permissions, and the [persistence limits](phase-9.md#bounds-and-privacy). Keep presets as regular local files, not symlinks, and avoid placing non-preset files in the preset library. |
| Browser Studio or Control Center is locked | Request a fresh link on the creator terminal. Tickets are one-use and expire after 90 seconds. A copied bare URL, reload, or a superseded link cannot restore authorization. |
| Link expired, revoked, or unavailable | Ask the creator for a new invite. A `127.0.0.1` URL works only on its own computer. An active simulation cannot be replayed by restoring history or opening another tab. |
| LAN browser cannot join | Confirm the intended private interface, the open join window, and that the devices can communicate on the same subnet. Guest/client isolation or a firewall may prevent access. Do not open public ports or use a tunnel. |
| LAN share refuses requests from its own host (`This listener is limited to its selected local address and subnet.`) | The address you selected is a bridge, typically `docker0` inside a container or CI runner. The kernel routes the host's own connection to that address through loopback, so the listener sees an out-of-subnet peer and refuses it by design. Open the share from a second device on the real LAN, or select an address assigned to that LAN interface. Do not widen the boundary: the refusal is containment working correctly. |
| Camera unavailable on the LAN scanner | Private LAN HTTP does not permit in-page camera capture. Use the phone's system QR scanner, select an image, or paste the link. |
| Bluetooth unavailable or unconfirmed | Check the reported OS/backend/hardware support before attempting discovery. Pair only with consent via the operating system. A transport ACK is not an invitation decision; use the separate QR/LAN workflow when no compatible transport is available. |

For ordinary problems submit a redacted report with app, Python, OS, and browser versions and whether the behavior was emulated. See the [security policy](../SECURITY.md) for private reports.
